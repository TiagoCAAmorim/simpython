# Dash-Based Plotting System - Implementation Plan

**Status:** Phase 4.2 completed (SR3 wrapper integrated; dual-map comparison view added)
**Date Created:** 2026-04-06
**Last Updated:** 2026-04-21

---

## Executive Summary

Migrate from Bokeh's static HTML plotting to Dash for interactive, lightweight visualizations supporting maps, line plots, scatter plots, and tables. This addresses issues with large file sizes generated by Bokeh and enables better browser compatibility.

---

## Current Implementation Summary

### Existing PlotHandler (Bokeh-based)
- **Location:** `rsimpy/cmg/sr3reader/plot.py`
- **Function:** Maps grid data to interactive polygon-based visualizations
- **Strengths:**
  - Polygon/cell-based grid visualization with custom geometry
  - Connection visualization (lines/arrows between cells)
  - Well visualization with types
  - Contour line generation
  - Hover tooltips for detailed information
  - Customizable colors, scales, and ranges

### Supporting Module (Bokeh)
- **Location:** `rsimpy/common/plot_utils.py`
- **Function:** Low-level plotting utilities for polygon grids
- **Key Functions:**
  - `plot_polygon_grid()`: Main visualization function
  - Contour line computation
  - Well visualization helpers
  - Color mapping and scaling
  - Connection visualization

### Current Architecture Pattern
```
sr3reader/plot.py (reads data from SR3)
    ↓
    calls
    ↓
common/plot_utils.py (numpy arrays as input)
    ↓
    creates
    ↓
Bokeh figures/panels
```

### Current Dash Implementation Snapshot
- `rsimpy/common/plot_dash.py` now provides the main Dash map renderer.
- Grid polygons render with sparse interior hover hit points instead of fill-based hover.
- Triangle connection hover is limited to center hit points so edge hover boxes do not appear.
- Default interaction is pan, with mouse-wheel zoom enabled and select/lasso removed from the modebar.
- Figure axes are locked to the global polygon bounds so reset axis returns to the full map extent.
- Contours use triangle-based line generation, global z-range levels, and a grayscale thick-line style.
- The left control panel groups grid, connection, and contour controls into separate blocks.
- `Show grid` hides both the property selector and the grid palette controls, and suppresses polygon rendering.
- Wells render as colored markers plus connecting lines, with visibility toggle and size control.
- `rsimpy/common/dash_app_template.py` is now a thin example launcher that delegates to reusable dashboard factories instead of carrying the inline Dash layout/callback tree.

## Requirements Summary

### 1. Multi-Plot Dashboard (NEW)
- Single page with multiple plot types
- Layout: maps, tables, line plots, scatter plots combined

### 2. Data Input Structure (Numpy-based)
- **Grid Data:** `[n_properties, n_days, n_cells]`
- **Layer Information:** Array indicating cells per layer
- **Vertices:** `[n_cells, 4, 3]` (4 vertices, x/y/z coordinates)
- **Connection Data:** `[n_connection_properties, n_days, n_connections]`
- **Connection Indices:** `[2, n_connections]` (cell pairs)
- **Wells:** Dictionary with cell indices per well name
- **Cells Names:** Optional list of strings
- **Line Plot X:** `[n_dates]` array
- **Line Plot Y:** `[n_properties, n_dates]` array
- **Scatter Plot:** Dictionary of `[n_values, 2]` arrays
- **Tables:** Pandas DataFrame

### 3. Map Visualization Features

#### Data Layer
- Multi-property grid visualization
- Time-series support (slider for days)
- Layer selection (slider for k)
- Property dropdown selector
- Cell-by-cell property display

#### Geometry & Style
- Quadrilateral polygons (4 sides)
- Customizable colors, palettes, line styles
- Z-based contour lines
- Polygon-to-layer mapping via mandatory layer array
- Global axis bounds for stable reset behavior
- Contours derived from triangle fan interpolation and rendered as thick grayscale lines

#### Connections
- Same-layer: thick black lines
- Cross-layer up: upward triangles (summed)
- Cross-layer down: downward triangles (summed)
- Optional provision (default: toggle unchecked if not provided)

#### Wells
- Visualization as circles with connecting lines
- Color-coded by type: prod=green, injw=blue, injg=red, inj=orange, closed=gray
- Size slider (5%-200%, default 20%)
- Optional toggle showing cross-layer connections
- Optional provision (empty dict default)

#### Interaction
- Hover: cell index, name, value
- Dropdowns: property selection
- Sliders: day and layer selection
- Toggles:
  - **Log scale** and **Asinh scale** (grid & connections): Always visible; disabled when corresponding Show toggle is False; mutually exclusive with each other; independent from Options toggle
  - Contour visibility, connection visibility, well visibility toggles
  - Options toggles for showing additional controls per section
- Mouse-wheel zoom enabled; select/lasso buttons removed; pan is the default drag mode
- Control groups hide when their visibility toggles are off
- Grid visibility toggle hides polygons, the property selector, and the grid palette together
- Toggle labels simplified (e.g., "Grid" instead of "Show grid"; "Log" for log-scale toggle)
- Log toggles positioned before Options toggles on the same line

#### Special Cases
- If std(z) < 1e-2: contour toggle disabled
- If no connections provided: connection controls disabled
- If grid is hidden: polygons are not shown and the grid/property controls are hidden
- Polygons drawn first, then connections, then contours, then wells (z-order)

### 4. Line Plot Features
- X-axis: dates (formatted appropriately)
- Y-axis: multiple properties `[n_properties, n_dates]`
- Optional second Y-axis (right side)
- Grid enabled
- Log-scale toggle

### 5. Scatter Plot Features
- Dictionary of `[n_values, 2]` arrays
- Property name as key

### 6. Table Features
- Pandas DataFrame input
- Interactive table display

## Analysis: What's Possible / Not Possible / Suggestions

### ✅ POSSIBLE

1. **Multi-plot dashboard**: Dash subplots or grid layout
2. **Interactive controls**: Dropdowns, sliders, toggles are standard Dash
3. **Data structures**: All proposed structures can be handled efficiently
4. **Layer selection**: Straightforward filtering with sliders
5. **Hover information**: Plotly's hovertemplate
6. **Color mapping**: Plotly colormaps and custom scales
7. **Well visualization**: Scatter + line segments
8. **Log scales**: Plotly native support
9. **Line plots with dual Y-axis**: Plotly secondary_y feature
10. **Tables**: Dash DataTable component
11. **Contour lines**: Computed before sending to Plotly (can reuse logic)
12. **File size**: Dash sends data separately from visualization code; smaller initial payload

### ⚠️ PARTIALLY POSSIBLE / REQUIRES ADAPTATION

1. **Triangle geometry for connections**:
   - Plotly doesn't have native triangle markers
   - **Solution**: Use `marker.symbol='triangle-up'` / `'triangle-down'` from scatter points, or use `add_shape()` with polygons
   - May not be as visually polished as Bokeh version

2. **Exact contour line computation**:
   - Can adapt existing `_compute_contour_lines_for_polygon()` logic
   - May need minor adjustments for coordinate systems
   - **Feasible**: Yes, with minor refactoring

3. **Complex cell naming and metadata**:
   - Hover will be more limited than Bokeh's rich HTML support
   - **Solution**: Use `hovertemplate` with tuple-based data keys

4. **Well connection line styling**:
   - Different colors for cross-layer connections
   - **Solution**: Create separate scatter/line traces for different connection types

### ❌ NOT POSSIBLE / VERY DIFFICULT

1. **None identified** - Dash + Plotly can address all major requirements

### 💡 SUGGESTIONS & IMPROVEMENTS

1. **Class Architecture**:
   ```
   common/plot_dash.py (general plotting)
   ├── DashMapPlot
   ├── DashLinePlot
   ├── DashScatterPlot
   └── DashTable

   common/plot_dashboard.py
   └── DashDashboard (combines all plots)

   sr3reader/plot_dash.py (sr3-specific)
   └── PlotHandlerDash (wrapper for sr3 data reading)
   ```

2. **Data Validation**: Implement robust validation for all input arrays early

3. **Caching Strategy**:
   - Option to cache contour line computation (expensive)
   - Store intermediate data (contours, triangle vertices) in dcc.Store

4. **Performance Optimization**:
   - Consider sampling for very large grids
   - Use WebGL rendering for dense scatter plots if needed

5. **File Size Concerns**:
   - Dash + Plotly will initially be smaller than Bokeh for single page
   - But multiple plots may increase JS payload
   - Monitor bundle size as features expand

6. **Data Structure Refinement**:
   - Property names should be list of strings
   - Provide array of layer sizes: `[n_layer_1, n_layer_2, ..., n_layer_nk]` (sum = n_cells)
   - This is more memory-efficient than per-cell layer assignment

## Data Structure Details (Refined)

### Grid Data
```python
# grid_data: np.ndarray, shape [n_properties, n_days, n_cells]
grid_data = np.random.rand(3, 5, 1000)  # 3 properties, 5 timesteps, 1000 cells

# property_names: list of str, len = n_properties
property_names = ['PRESSURE', 'SO', 'PERMX']

# If not provided, auto-create:
property_names = ['Cell Index']  # All zeros except values are cell indices
```

### Layer Information
```python
# layer_sizes: np.ndarray, shape [n_layers,]
# Sum of elements = n_cells
layer_sizes = np.array([250, 300, 450])  # 3 layers with 250, 300, 450 cells respectively

# Alternative (also support but recommend layer_sizes):
# layer_per_cell: np.ndarray, shape [n_cells,]
# Values are 1-indexed layer numbers
```

### Vertices
```python
# vertices: np.ndarray, shape [n_cells, 4, 3]
# Last dimension: [x, y, z]
vertices = np.random.rand(1000, 4, 3)

# Mandatory - no default
```

### Connections
```python
# connection_indices: np.ndarray, shape [2, n_connections]
# Values are 0-indexed cell indices (max value < n_cells)
connection_indices = np.array([[0, 5], [1, 6], [5, 10]], dtype=int).T

# connection_data: np.ndarray, shape [n_connection_properties, n_days, n_connections]
connection_data = np.random.rand(1, 5, 3)  # 1 property, 5 timesteps, 3 connections

# If not provided: no connections tab/toggle shown
```

### Wells
```python
# wells: dict
# Keys: "well_name,type" where type in ['prod', 'injw', 'injg', 'inj', 'closed']
# Values: np.ndarray of 0-indexed cell indices
wells = {
    "WELL-A,prod": np.array([10, 35, 60]),   # cells in layers
    "WELL-B,injw": np.array([100, 125])
}

# If not provided: empty dict {}
```

### Cell Names
```python
# cell_names: list of str, len = n_cells
# Optional
cell_names = [f"Cell_{i}" for i in range(n_cells)]
```

### Line Plot
```python
# x_data: np.ndarray, shape [n_dates,]
x_data = np.array([0, 10, 50, 100, 365])  # Days

# y_data: np.ndarray, shape [n_properties, n_dates]
y_data = np.random.rand(3, 5)

# y_names: list of str, len = n_properties
y_names = ['PRESSURE', 'SO', 'SG']

# y_right: optional, np.ndarray shape [n_right_properties, n_dates]
y_right = np.random.rand(1, 5)

# y_right_names: optional, list of str
y_right_names = ['VISCOSITY']
```

### Scatter Plot
```python
# scatter_data: dict
# Keys: property names, Values: np.ndarray shape [n_points, 2]
scatter_data = {
    'PVT Data': np.random.rand(100, 2),
    'Other Data': np.random.rand(50, 2)
}
```

### Table
```python
# table_data: pd.DataFrame
import pandas as pd
table_data = pd.DataFrame({...})
```

### Running Examples

```bash
# Generic nested-tab dashboard (synthetic data)
python -m rsimpy.common.dash_app_template --example step4generic

# SR3-backed dashboard (requires tests/sr3/base_case_3a.sr3)
python -m rsimpy.common.dash_app_template --example sr3

# Dual-map comparison (synthetic data)
python -m rsimpy.common.dash_app_template --example compare
```

Open the local URL shown by Dash (typically `http://127.0.0.1:8050`).

**Generic wrapper** (`step4generic`):
- Grouped tabs by panel type (Maps, Line Plots, Scatter Plots, Tables)
- Nested tabs inside each type using dictionary keys as tab labels
- Independent callbacks auto-wired per panel; slider tooltips; color limits UI

**Compare** (`compare`):
- Two maps with a shared control panel
- Axes sync on pan/zoom via `Patch()` (efficient partial layout update)
- Shared auto-synced color limits from combined data range; manual override supported
- Side-by-side or stacked layout toggle

## Known Issues & Mitigations

| Issue | Impact | Mitigation |
|-------|--------|-----------|
| Triangle geometry in Plotly | Visual fidelity | Use special marker symbols or polygon shapes |
| Large grids (>10k cells) | Performance | Add sampling option or use WebGL |
| Contour computation overhead | Load time | Cache results in dcc.Store |
| Cross-browser differences | Compatibility | Test on Chrome, Firefox, Safari |
